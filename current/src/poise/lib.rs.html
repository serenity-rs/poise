33# Introduction to serenity
34
35Serenity is the Discord API wrapper library poise is built on top of. Using poise automatically
36means using serenity, so here's a couple tips:
37
38## `impl Trait` parameters
39
40Many serenity functions take an argument of type [`impl CacheHttp`](serenity::CacheHttp) or
41[`impl AsRef<Http>`](serenity::Http). You can pass in any type that implements these traits, like
42[`crate::Context`] or [`serenity::Context`].
43
44## Gateway intents
45
46To run a Discord bot, you need to set _gateway intents_: a list of event types you want to receive
47from Discord. A sensible default is [`serenity::GatewayIntents::non_privileged()`] which contains
48all event types except privileged ones. Privileged intents require manual enabling in your bot
49dashboard to use (and large bots require whitelisting by Discord). A notable privileged intent
50is [MESSAGE_CONTENT](serenity::GatewayIntents::MESSAGE_CONTENT) which is required for poise prefix
51commands.
52
53To set multiple gateway events, use the OR operator:
54`serenity::GatewayIntents::non_privileged() | serenity::GatewayIntents::MESSAGE_CONTENT`
55
56## Discord actions outside a command
57
58You can run Discord actions outside of commands by cloning and storing [`serenity::CacheHttp`]/
59[`Arc<serenity::Http>`](serenity::Http)/[`Arc<serenity::Cache>`](serenity::Cache). You can get
60those either from [`serenity::Context`] (passed to
61[`setup`](crate::FrameworkBuilder::setup) and all commands via
62[`ctx.serenity_framework()`](crate::Context::discord)) or before starting the client via
63[`http`](serenity::Client::http) and [`cache`](serenity::Client::cache).
64
65Pass your `CacheHttp` or `Arc<Http>` to serenity functions in place of the usual
66`serenity::Context`
67
68## Useful serenity methods
69
70Many serenity structs have an ID field. Some useful methods are defined only on the Id types.
71For example:
72- [`serenity::Guild`] and [`serenity::GuildId`]
73- [`serenity::User`] and [`serenity::UserId`]
74- [`serenity::Role`] and [`serenity::RoleId`]
75- ...
76
77Some examples for methods you should have in your repertoire:
78- [`serenity::GuildId::to_guild_cached`] and [`serenity::GuildId::to_partial_guild`] to access full
79    guild data
80- [`serenity::ChannelId::to_channel`] to access full channel data
81- [`serenity::Channel::guild`] to try convert a generic [`serenity::Channel`] into a
82    [`serenity::GuildChannel`], to access guild specific channel data

84# Introduction to slash commands
85
86Discord slash commands can be a bit unintuitive at first. If you're unfamiliar, please read this
87
88To activate a slash command, your bot
89needs to _register_ it on Discord. You may want to do this manually, with a `register` command
90(poise provides [`builtins::register_application_commands_buttons`] as a starting point for that), or you
91may want to re-register commands automatically on every bot startup. Choose what you prefer. Also
92see [Registering Slash Commands](#registering-slash-commands).
93
94Commands can be registered _globally_ or _per guild_. Global commands are available on every guild
95your bot is invited on, but it takes up to an hour for global registration to roll out. Per guild
96registration only updates a single guild, but it happens instantly, which is useful for testing.
97
98Your bot also needs to be invited with the `applications.commands` scope. For example, in Discord's
99invite link generator (discord.com/developers/applications/XXX/oauth2),
100tick the `applications.commands` box.
101
102# How to use
103
104## Create commands
105Every command is represented by a function annotated with [`#[poise::command]`](command):
106
107```rust
108# type Error = Box<dyn std::error::Error + Send + Sync>;
109# type Context<'a> = poise::Context<'a, (), Error>;
110# use poise::serenity_prelude as serenity;
111/// Description of the command here
112///
113/// Here you can explain how the command \
114/// is used and how it works.
115#[poise::command(prefix_command, /* add more optional command settings here, like slash_command */)]
116async fn command_name(
117    ctx: Context<'_>,
118    #[description = "Description of arg1 here"] arg1: serenity::Member,
119    #[description = "Description of arg2 here"] arg2: Option<u32>,
120) -> Result<(), Error> {
121    // Command code here
122
123    Ok(())
124}
125```
126
127See [`#[poise::command]`](command) for detailed information.
128
129### Subcommands
130Commands in poise have a tree structure. Every commands refers to a list of subcommands, which you
131can easily set using the [`command`] macro like so:
132
133```rust
134# type Error = Box<dyn std::error::Error + Send + Sync>;
135# type Context<'a> = poise::Context<'a, (), Error>;
136#[poise::command(prefix_command, slash_command, subcommands("child1", "child2"))]
137pub async fn parent(ctx: Context<'_>, arg: String) -> Result<(), Error> { Ok(()) }
138
139#[poise::command(prefix_command, slash_command)]
140pub async fn child1(ctx: Context<'_>, arg: String) -> Result<(), Error> { Ok(()) }
141#[poise::command(prefix_command, slash_command)]
142pub async fn child2(ctx: Context<'_>, arg: String) -> Result<(), Error> { Ok(()) }
143```
144
145With this setup, users can call `~parent [arg]` or `~parent child1 [arg]` or `~parent child2 [arg]`.
146Slash command subcommands are also supported, but the base command (`/parent`) [cannot be used](https://docs.discord.com/developers/interactions/application-commands#subcommands-and-subcommand-groups)
147as per Discord; only the leaf commands (`/parent child1 [arg]`, `/parent child2 [arg]`).
148
149When adding the commands to the framework, add just the parent command (since it fully contains its
150subcommands):
151
152```rust
153# type Error = Box<dyn std::error::Error + Send + Sync>;
154# type Context<'a> = poise::Context<'a, (), Error>;
155# #[poise::command(prefix_command)]
156# pub async fn parent(ctx: Context<'_>, arg: String) -> Result<(), Error> { Ok(()) }
157let options = poise::FrameworkOptions {
158    commands: vec![
159        parent(),
160    ],
161    ..Default::default()
162};
163```
164
165Subcommands are stored in [`Command::subcommands`]. As with all [`Command`] fields, you can
166programmatically modify those any way you'd like. The [`command`] macro is just a convenience thing
167to set the fields for you.
168
169For another example of subcommands, see `examples/feature_showcase/subcommands.rs`.
170
171### Big example to showcase many command features
172
173Also see the [`command`] macro docs
174
175```rust
176use poise::serenity_prelude as serenity;
177type Data = ();
178type Error = Box<dyn std::error::Error + Send + Sync>;
179type Context<'a> = poise::Context<'a, Data, Error>;
180
181/// A test command for poise
182#[poise::command(
183    prefix_command,
184    track_edits,
185    hide_in_help,
186    required_permissions = "SEND_MESSAGES",
187    aliases("bigounce", "abomination"),
188    help_text_fn = "my_huge_ass_command_help",
189    check = "check",
190    on_error = "error_handler",
191)]
192async fn my_huge_ass_command(
193    ctx: Context<'_>,
194    #[description = "Consectetur"] ip_addr: std::net::IpAddr, // implements FromStr
195    #[description = "Amet"] user: serenity::Member, // implements ArgumentConvert
196    #[description = "Sit"] code_block: poise::CodeBlock, // implements PopArgument
197    #[description = "Dolor"] #[flag] my_flag: bool,
198    #[description = "Ipsum"] #[lazy] always_none: Option<String>,
199    #[description = "Lorem"] #[rest] rest: String,
200) -> Result<(), Error> {
201    Ok(())
202}
203
204fn my_huge_ass_command_help() -> String {
205    String::from("\
206Example usage:
207~my_huge_ass_command 127.0.0.1 @kangalio `i = i + 1` my_flag rest of the message")
208}
209
210async fn check(ctx: Context<'_>) -> Result<bool, Error> {
211    // We discriminate against users starting with an X
212    Ok(!ctx.author().name.starts_with('X'))
213}
214
215async fn error_handler(error: poise::FrameworkError<'_, Data, Error>) {
216    println!("Oh noes, we got an error: {:?}", error);
217}
218```

220## Create and configure framework
221
222```rust
223# use std::sync::Arc;
224# type Error = Box<dyn std::error::Error + Send + Sync>;
225# type Context<'a> = poise::Context<'a, (), Error>;
226# async fn my_error_function(_: poise::FrameworkError<'_, (), Error>) {}
227# #[poise::command(prefix_command)] async fn command1(ctx: Context<'_>) -> Result<(), Error> { Ok(()) }
228# #[poise::command(prefix_command)] async fn command2(ctx: Context<'_>) -> Result<(), Error> { Ok(()) }
229# #[poise::command(prefix_command)] async fn command3(ctx: Context<'_>) -> Result<(), Error> { Ok(()) }
230use poise::serenity_prelude as serenity;
231
232# async {
233// Use `Framework::builder()` to create a framework builder and supply basic data to the framework:
234
235let framework = poise::Framework::builder()
236    .setup(|_, _, _| Box::pin(async move {
237        // construct user data here (invoked when bot connects to Discord)
238        Ok(())
239    }))
240
241    // Most configuration is done via the `FrameworkOptions` struct, which you can define with
242    // a struct literal (hint: use `..Default::default()` to fill uninitialized
243    // settings with their default value):
244    .options(poise::FrameworkOptions {
245        on_error: |err| Box::pin(my_error_function(err)),
246        prefix_options: poise::PrefixFrameworkOptions {
247            prefix: Some("~".into()),
248            edit_tracker: Some(Arc::new(poise::EditTracker::for_timespan(std::time::Duration::from_secs(3600)))),
249            case_insensitive_commands: true,
250            ..Default::default()
251        },
252        // This is also where commands go
253        commands: vec![
254            command1(),
255            command2(),
256            // You can also modify a command by changing the fields of its Command instance
257            poise::Command {
258                // [override fields here]
259                ..command3()
260            }
261        ],
262        ..Default::default()
263    }).build();
264
265let client = serenity::ClientBuilder::new("...", serenity::GatewayIntents::non_privileged())
266    .framework(framework).await;
267
268client.unwrap().start().await.unwrap();
269# Ok::<(), Error>(()) };
270```

272## Registering slash commands
273
274As explained in [Introduction to slash commands](#introduction-to-slash-commands), slash
275commands need to be _registered_ to Discord. Poise provides several ways to do it, with varying
276degree of abstraction. (Note: you can access a list of framework commands from anywhere with
277[`ctx.framework().options.commands`](Context::framework)).
278
279The easiest way is with [`builtins::register_application_commands_buttons`].
280It spawns a message with buttons to register and unregister all commands, globally or in the current
281guild (see its docs).
282
283A more flexible approach is to serialize the commands to a [`Vec<serenity::CreateCommand>`]
284using [`builtins::create_application_commands`]. That way, you can call serenity's registration
285functions manually:
286- [`serenity::Command::set_global_commands`]
287- [`serenity::GuildId::set_commands`]
288
289For example, you could call this function in [`FrameworkBuilder::setup`] to automatically
290register commands on startup. Also see the docs of [`builtins::create_application_commands`].
291
292The lowest level of abstraction for registering commands is [`Command::create_as_slash_command`]
293and [`Command::create_as_context_menu_command`].

320## Unit testing
321
322Unit testing a Discord bot is difficult, because mocking the Discord API is an uphill battle.
323Your best bet for unit testing a Discord bot is to extract the "business logic" into a separate
324function - the part of your commands that doesn't call serenity functions - and unit test that.
325
326Example:
327
328```rust
329# type Error = Box<dyn std::error::Error>;
330# type Context<'a> = poise::Context<'a, (), Error>;
331#[poise::command(slash_command)]
332pub async fn calc(ctx: Context<'_>, expr: String) -> Result<(), Error> {
333    let ops: &[(char, fn(f64, f64) -> f64)] = &[
334        ('+', |a, b| a + b), ('-', |a, b| a - b), ('*', |a, b| a * b), ('/', |a, b| a / b)
335    ];
336    for &(operator, operator_fn) in ops {
337        if let Some((a, b)) = expr.split_once(operator) {
338            let result: f64 = (operator_fn)(a.trim().parse()?, b.trim().parse()?);
339            ctx.say(format!("Result: {}", result)).await?;
340            return Ok(());
341        }
342    }
343    ctx.say("No valid operator found in expression!").await?;
344    Ok(())
345}
346```
347
348Can be transformed into
349
350```rust,no_run
351# type Error = Box<dyn std::error::Error>;
352# type Context<'a> = poise::Context<'a, (), Error>;
353fn calc_inner(expr: &str) -> Option<f64> {
354    let ops: &[(char, fn(f64, f64) -> f64)] = &[
355        ('+', |a, b| a + b), ('-', |a, b| a - b), ('*', |a, b| a * b), ('/', |a, b| a / b)
356    ];
357    for &(operator, operator_fn) in ops {
358        if let Some((a, b)) = expr.split_once(operator) {
359            let result: f64 = (operator_fn)(a.trim().parse().ok()?, b.trim().parse().ok()?);
360            return Some(result);
361        }
362    }
363    None
364}
365
366#[poise::command(slash_command)]
367pub async fn calc(ctx: Context<'_>, expr: String) -> Result<(), Error> {
368    match calc_inner(&expr) {
369        Some(result) => ctx.say(format!("Result: {}", result)).await?,
370        None => ctx.say("Failed to evaluate expression!").await?,
371    };
372    Ok(())
373}
374
375// Now we can test the function!!!
376#[test]
377fn test_calc() {
378    assert_eq!(calc_inner("4 + 5"), Some(9.0));
379    assert_eq!(calc_inner("4 / 5"), Some(0.2));
380    assert_eq!(calc_inner("4 ^ 5"), None);
381}
382```

435/// Shorthand for a wrapped async future with a lifetime, used by many parts of this framework.
436///
437/// An owned future has the `'static` lifetime.
438pub type BoxFuture<'a, T> = std::pin::Pin<Box<dyn std::future::Future<Output = T> + Send + 'a>>;
439
440/// Internal wrapper function for catch_unwind that respects the `handle_panics` feature flag
441async fn catch_unwind_maybe<T>(
442    fut: impl std::future::Future<Output = T>,
443) -> Result<T, Option<String>> {
444    #[cfg(feature = "handle_panics")]
445    let res = futures_util::FutureExt::catch_unwind(std::panic::AssertUnwindSafe(fut))
446        .await
447        .map_err(|e| {
448            if let Some(s) = e.downcast_ref::<&str>() {
449                Some(s.to_string())
450            } else if let Ok(s) = e.downcast::<String>() {
451                Some(*s)
452            } else {
453                None
454            }
455        });
456    #[cfg(not(feature = "handle_panics"))]
457    let res = Ok(fut.await);
458    res
459}
